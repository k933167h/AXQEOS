AX QE OS v4.9 운영 Runbook

초보자용 · GitHub: 공식 저장소 · 기준: 개발 브랜치 통합 전

설치테스트승인장애 대응증빙

1. 설치 및 설정

Docker와 Docker Compose를 설치하고 저장소를 복제합니다. .env.example을 .env로 복사한 뒤 AX_REPORTER_TOKEN, AX_SME_TOKEN, GRAFANA_ADMIN_PASSWORD에 충분히 긴 서로 다른 값을 입력합니다. 비밀키는 Git에 올리지 마세요.

git clone https://github.com/k933167h/AXQEOS.git
cd AXQEOS
cp .env.example .env
# .env 파일을 편집한 후
docker compose up --build -d
curl http://127.0.0.1:8080/health

환경 변수와 외부 API 연결이 없는 상태에서는 외부 전송이 실패할 수 있습니다.

2. Reporter 사용

테스트 도구는 /api/v1/reporter에 JSON 결과를 전송합니다. 필수 항목은 external_run_id, test_id, risk이며 인증 헤더 X-AX-Reporter-Token을 사용합니다.

curl -X POST http://127.0.0.1:8080/api/v1/reporter \
 -H 'Content-Type: application/json' \
 -H 'X-AX-Reporter-Token: YOUR_REPORTER_TOKEN' \
 -d '{"external_run_id":"demo-1","test_id":"demo","risk":0.2,"assertion_passed":false}'

TesterArmy 실제 브라우저 실행은 별도 도구 설치와 검증이 필요합니다. reporter/testerarmy.spec.ts는 연동 예제이며 운영 검증 완료본이 아닙니다.

3. 전문가 승인

검토(review) 결과만 SME 승인을 받을 수 있습니다. 승인 API와 Golden 승격 API는 별개이며 X-AX-SME-Token이 필요합니다. 공유 토큰 방식은 운영 도입 전 사용자별 인증으로 강화해야 합니다.

4. 장애 대응

API 상태: /health · 지표: /metrics · 컨테이너 로그: docker compose logs api worker. 외부 전송 실패는 SQLite outbox에 기록되며 최대 6회 시도 후 dead 상태로 전환됩니다. 자동 재처리 기능은 아직 확인되지 않았습니다.

5. 검증 및 감사

개발자 테스트: python -m pytest -q. 실행 결과, 승인 기록, Golden 승격 기록을 보존합니다. 개인정보나 환자 데이터를 공개 저장소 또는 테스트 증빙에 넣지 마세요.

현재 구현 상태와 향후 ScientistTwo 확장 계획은 Architecture Overview를 참조하세요.
